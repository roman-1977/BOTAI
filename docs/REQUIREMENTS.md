# Product Requirements

Документ содержит подтверждённые и предварительные продуктовые требования.

## 1. Структура контента

Учебный материал должен иметь иерархическую структуру.

Предварительная модель:

**направление / курс → предмет → раздел → тема → опросник → задания**

Точная модель будет определена позже.

Пользователь должен иметь возможность:

- подключать весь курс;
- подключать отдельные предметы;
- подключать разделы;
- подключать отдельные темы;
- добавлять новые темы к уже используемому материалу.

## 2. Типы заданий BOTAI

### 2.1 Пара / соответствие

Пример:

`H₂SO₄ ↔ серная кислота`

Показывается одна сторона.

Пользователь вспоминает вторую, открывает ответ и самостоятельно оценивает результат.

Для задания может быть разрешена проверка в обоих направлениях.

Пример:

`H₂SO₄ → серная кислота`

и

`серная кислота → H₂SO₄`

Автор должен иметь возможность запретить обратное направление.

### 2.2 Вопрос → ответ

Пример:

`Формула площади круга?`

Ответ:

`S = πr²`

Обратное направление отсутствует.

После показа ответа пользователь оценивает собственное знание.

### 2.3 Выбор вариантов

Вопрос содержит несколько вариантов ответа.

Настройки должны позволять:

- один правильный ответ;
- несколько правильных ответов;
- показывать количество правильных вариантов;
- не показывать количество правильных вариантов.

Пользователь выбирает ответы и завершает попытку.

Система автоматически проверяет результат.

## 3. Форматы содержимого

Задание потенциально должно поддерживать:

- обычный текст;
- формулы;
- изображения;
- схемы;
- чертежи.

Особенно важно обеспечить пригодность для:

- математики;
- физики;
- химии;
- биологии.

## 4. Самооценка ответа

Для заданий с ручной проверкой предварительно рассматривается шкала:

- Не знаю
- С трудом
- Знаю

Точная шкала ещё не утверждена.

## 5. Планирование повторений

Система должна вести историю знания каждого изучаемого элемента.

На основании истории BOTAI должен определять:

- что пользователь знает;
- что знает неуверенно;
- что не знает;
- что пора повторить;
- что можно временно не показывать.

Конкретный алгоритм интервального повторения пока не выбран.

## 6. Ежедневная программа

Главный сценарий не должен требовать от пользователя самостоятельно выбирать колоду для занятия.

BOTAI должен формировать рекомендуемое занятие.

Пример:

- 12 повторений;
- 8 слабых элементов;
- 7 новых;
- ориентировочно 18 минут.

Основное действие:

**БОТАТЬ**

## 7. Цели

Пользователь должен иметь возможность задавать цели.

Пример:

`ЕГЭ по химии — 4 июня`

Система должна учитывать:

- дату цели;
- объём подключённого материала;
- текущий прогресс;
- доступное время;
- требуемый темп.

BOTAI должен показывать, идёт ли пользователь по плану.

## 8. Библиотека

Должна существовать библиотека готовых учебных материалов.

Материал должен иметь как минимум:

- название;
- описание;
- автора;
- структуру;
- количество заданий;
- дату обновления;
- версию.

Пользователь должен иметь возможность добавлять публичный материал себе.

## 9. Пользовательский контент

Пользователь должен иметь возможность создавать собственные опросники.

В перспективе возможны режимы публикации:

- только для себя;
- по ссылке / ограниченной группе;
- публично для всех.

Публичный материал может требовать модерации.

## 10. Обновление материалов

Если автор изменил опубликованный материал, пользователь должен иметь возможность получить обновление.

При обновлении необходимо по возможности сохранить накопленную статистику пользователя.

## 11. AI-экзамен — BOLDAI

AI-экзамен является отдельным режимом от зубрёжки.

AI использует материал выбранной темы как источник истины.

AI может создавать новые формулировки вопросов на основании этого материала.

Экзамен должен проверять не только воспроизведение, но и понимание связей между изученными фактами.

Возможные интерфейсы:

- текстовый диалог;
- голосовой диалог.

## 12. Результат AI-экзамена

Экзамен должен показывать не только общий балл.

Желательно определять:

- хорошо освоенные части;
- слабые части;
- обнаруженные пробелы;
- материал, который стоит повторить.

После экзамена пользователь должен иметь возможность запустить:

**ЗАБОТАТЬ ПРОБЕЛЫ**

## 13. Статистика

Необходимо различать как минимум:

- уровень запоминания;
- результаты проверки понимания.

Также предполагаются:

- динамика;
- история занятий;
- время занятий;
- количество изученного;
- движение к цели;
- недельные отчёты.

## 14. Социальные функции

В дальнейшем предполагаются:

- друзья;
- возможность делиться результатами;
- челленджи;
- совместные цели;
- мотивационные механики.

Конкретная модель пока не утверждена.

## 15. Мотивация

Приложение должно мотивировать заниматься регулярно.

Возможные механики:

- серии занятий;
- достижения;
- прогресс к цели;
- недельные отчёты;
- челленджи;
- лёгкий современный / мемный язык интерфейса.

Мемы не должны быть частью фундаментального бренда, поскольку быстро устаревают.

## 16. Импорт и AI-создание контента

Рассматриваются для будущих версий:

- PDF;
- фотографии;
- документы;
- таблицы;
- AI-генерация учебного набора из исходного материала.

Требования к этой функции ещё не определены.
